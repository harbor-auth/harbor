# Proposal: "Sign in with Private Harbor" button + brand kit

## Problem

Relying parties (RPs) integrating Harbor today have no official button assets,
no vendored integration example, and no single doc explaining the RP's
security responsibilities (state, nonce, PKCE, redirect allowlisting, session
rotation, callback error handling). Without a kit, RPs either hand-roll a
button (inconsistent branding, missed a11y states) or hand-build an
`/authorize` URL client-side (the classic CSRF/PKCE-bypass footgun this
project's own invariants — `INV-PKCE-MANDATORY`, `INV-REDIRECT-EXACT` — exist
to catch server-side, but cannot prevent an RP from omitting client-side).
Harbor Cloud onboarding and `harbor-dummy-app` both need a reusable kit today
and neither can depend on AGPL-licensed code.

## Proposed Solution

Ship `sdk/sign-in-button/` as a new, standalone, **Apache-2.0** subtree
(REUSE.toml override, matching the existing `api/`/`deploy/` precedent for
permissive external consumption):

- Deterministic SVG brand assets (logomark + button, light/dark/neutral ×
  compact/full, hover/focus/disabled states) generated by a small Go
  generator so output is reproducible and vendored/versioned (no remote
  tracking script, no CDN dependency).
- Copy-paste CSS + plain HTML example, and a dependency-light React
  component (peer dep: `react` only) — all targeting the **RP's own
  login-initiation endpoint**, never a hand-built `/authorize` URL.
- A minimal, executable Go RP example (`examples/minimal-rp/`) that
  demonstrates the RP-owned responsibilities end to end: CSPRNG state,
  PKCE S256 verifier/challenge, nonce, redirect-URI allowlisting, callback
  verification, and generic error mapping.
- Contract tests proving the example/button integration **cannot** produce a
  link that omits `state` or `code_challenge`/`code_challenge_method=S256`,
  and that asset generation is byte-deterministic across runs.
- Documentation: an OIDC integration guide (discovery, public vs.
  confidential clients, PKCE S256, scopes/consent, PPID `sub`, logout,
  refresh rotation, JWKS rotation, error codes, CSP), an RP security-
  responsibilities guide, and a brand-misuse + evidence-backed privacy
  guide (no certification/compliance claims without proof).

## Non-Goals

- No changes to Harbor's OIDC server behavior (`internal/oidc*`) — this is a
  purely additive, RP-facing artifact.
- No hosted/CDN-served script or remote tracking pixel — assets are vendored.
- No SAML, no non-OIDC protocol support.
- No actual Harbor Cloud onboarding or `harbor-dummy-app` code changes (both
  live outside this repo) — only ensuring the kit is import-ready for them.

## Impact

New subtree only: `sdk/sign-in-button/`, `REUSE.toml` (one new override
block). No existing package is modified.
